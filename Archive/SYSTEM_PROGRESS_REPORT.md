# 시스템 모델 및 설계 진행 상황 보고서 (중간발표 및 후속 개발 대비)

## 1. 프로젝트 개요 및 역할 분담 (논문 및 시스템)
본 프로젝트는 **KCC 2026 논문 제출 (주제: GPU AI 워크로드 벤치마크 성능 분석)** 과 연계되어 있으며, 선입견(예: 최신 GPU나 큰 메모리가 무조건 좋을 것이다 등)을 실제 벤치마크 실험으로 검증하는 것을 목표로 합니다.

*   **연구 및 실험 (AI 워크로드 벤치마크 파트)**: 교내 가용 GPU(RTX 3090, 4090, 6000 등)와 유료 고사양 GPU 환경에서 모델별 성능(시간, 메모리 등) 측정 및 가설 증명 실험 진행.
*   **시스템 개발 (웹 대시보드 및 서버 파트 - 본인 주력 담당)**: 다양한 GPU 분산 노드를 하나로 묶어 연구자들이 쉽게 컨테이너 리소스를 할당받고 워크로드를 관리할 수 있는 **통합 웹 대시보드 및 분산 아키텍처 시스템** 개발.

---

## 2. 현재까지의 구현 현황 (웹 대시보드 및 시스템 중심)

현재 본인이 개발 중인 시스템은 중앙 서버(Central)와 실제 GPU가 장착된 분산 노드(Worker)를 분리하여 운용하는 **Relay-Only Allocation 및 Worker-Direct Session 구조**로 뼈대를 완성한 상태입니다.

### 가. 프론트엔드 (웹 대시보드 파트 - 메인 담당)
*   **핵심 대시보드 UI 구현**: React, Tailwind CSS를 활용해 접속 사용자가 본인에게 할당된 컨테이너 현황을 확인·삭제하고, 유휴 GPU 자원 목록을 쉽게 볼 수 있는 시스템 대시보드 뷰 렌더링 구현을 1차적으로 완료했습니다.
*   **API 연동 및 통신 이슈 해결**: Axios를 통하여 백엔드 REST API를 비동기 호출되도록 연동 성공하였고, 포트 분리로 인한 Proxy 및 CORS 정책 이슈 문제를 해결하였습니다.

### 나. 백엔드 및 인프라
*   **데이터베이스 마이그레이션 및 인증**: 사용자 관리를 위해 H2에서 PostgreSQL로 데이터베이스 마이그레이션을 완료했으며, Spring Security + JWT 기반의 무상태 인증(회원가입, 로그인) 로직을 적용했습니다.
*   **코어 도메인 API 구현**: Relay 서버와 Remote Worker 간 비동기 소켓 통신을 매개로, Docker 컨테이너 자원을 원격 생성/조회/삭제하는 핵심 파이프라인 개발을 완료했습니다.
*   **단일/분산 배포 인프라 (Docker)**: 개발 환경뿐 아니라 **실제 외부 컴퓨터에 설치된 여러 대의 연구실 GPU(3090, 4090 등)** 서버들을 연동할 수 있도록 `docker-compose.central`, `docker-compose.worker` 형태의 분리 배포 템플릿 환경을 구축했습니다.

## 3. 향후 구현 계획 (중간발표 및 최종 목표)

중간발표에서는 진행 중인 `벤치마크 실험 결과` 발표와 함께, 앞으로 본인이 **'웹 대시보드'와 '시스템 아키텍처'를 어떻게 확장하고 실제 인프라로 구성할지** 상세한 계획과 시각 자료를 제시할 것입니다. 

### 가. 시스템 전체 구성도(Architecture Diagram) 시각화
*   현재 개발된 Relay-Worker 분산 서버 구조를 바탕으로 향후 쿠버네티스(Kubernetes) 혹은 현재의 분리 배포 기반 클러스터링 모델로 어떻게 관리할지 나타내는 전체 시스템 구성 다이어그램 작성.
*   구성도 내에 **본인이 담당하는 '통합 모니터링 대시보드 영역'**과 다른 팀원이 수행하는 **'AI 워크로드 벤치마크 실행 영역(Worker Node)'**의 역할을 시각적으로 명확히 분리하여 중간발표 자료에 포함.

### 나. 대시보드 기능 확장 및 예상 화면(Mock-up) 제작
*   **GPU 노드별 실시간 부하 모니터링 뷰**: 3090, 4090, 6000 등의 각 Worker 노드에서 벤치마크 실행 시 변동되는 VRAM 사용량, 온도, 전력 상태를 실시간 스파크라인(시계열 통계 차트) 형태로 사용자에게 그려주는 대시보드 UI 프로토타입 작성.
*   **벤치마크 통합 리포트 화면**: 단순히 컨테이너 목록만 부여하는 것을 넘어, 다른 팀원들이 실험하고 있는 벤치마크 메트릭 결과를 시스템 대시보드에서도 조회할 수 있도록 확장하는 기획안.
*   **인웹 (In-Web) 연결 터미널 에뮬레이터 연동**: 접속 포트를 반환받는 현재의 불편함을 해소하고자, 브라우저 화면에서 할당된 컨테이너 내부 셸(Shell)로 직접 명령어를 입력하고 벤치마크 스크립트를 켤 수 있는 웹 터미널 기능 개발 계획 제시.

### 다. 실제 가용 GPU 환경 대상 연동 및 시스템 구축
*   회의에서 언급된 **별도 컴퓨터에 장착된 3대의 GPU(3090, 4090, 6000)**에 `session-worker` 시스템을 배포하고, 현재 개발 중인 중앙 백엔드/대시보드와 네트워크 통신 채널을 뚫어 실제 서비스를 탑재하는 절차 진행.
*   워크로드 특성(Compute-bound vs. Memory-bound) 기반의 GPU 리소스 분배 스케줄링 맞춤 알고리즘 적용 여부 설계 검토 (향후 방향성).
