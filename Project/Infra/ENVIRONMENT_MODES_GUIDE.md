# 🌍 로컬 개발 vs 도커 배포 환경 가이드 (포트 5173 vs 4000)

프로젝트를 실행할 때 헷갈릴 수 있는 **프론트엔드 포트(5173과 4000)의 차이점과 정확한 개념, 실행 방법**을 명확하게 정리한 안내 문서입니다.

## 🎯 핵심 개념 요약

| 구분 | 포트 번호 | 용도 | 구동 방식 |
| :--- | :--- | :--- | :--- |
| **로컬 개발용** | `localhost:5173` | UI 실시간 수정 및 개발 (Hot-Reloading) | `npm run dev` (Vite) |
| **도커 배포용** | `localhost:4000` | 운영 환경과 동일한 통합 테스트 및 최종 배포 | `docker compose` (Nginx) |

---

## 1️⃣ 로컬 개발용 모드 (5173 포트)

### 💡 개념: 코드를 고치면 즉시 화면에 반영 (Vite Dev Server)
프론트엔드쪽 **"코드를 짜고 활발하게 개발할 때"** 반드시 사용하는 모드입니다. 
**Hot-Reloading(핫 리로딩)** 기술이 적용되어 있어서, 텍스트 편집기(VS Code 등)에서 코드를 수정하고 저장(Ctrl+S)하는 순간 브라우저 창을 새로고침하지 않아도 바뀐 변경 사항이 곧바로 화면에 나타납니다. 

빠른 반응 속도를 위해 파일 용량을 줄이기 위한 압축(포장, build) 과정을 건너뛰고 원본 상태 그대로 메모리 위에서 구동합니다.

### ❓ 언제 사용하나요?
- 프론트엔드 UI/UX 디자인을 한참 수정 중일 때
- React 컴포넌트나 상태 관리 로직을 계속해서 변경해가며 실험이 필요할 때

### 💻 실행 방법 (터미널 창 추가 필요)
명령어는 반드시 `Frontend` 폴더 안으로 직접 들어가서 쳐야 적용됩니다.
```bash
cd Frontend
npm install
npm run dev
```
👉 **접속 주소:** `http://localhost:5173`

## 2️⃣ 도커 배포용 / 통합 실행 모드 (4000 포트)

### 💡 개념: 실제 운영 환경 똑같이 흉내 낸 통짜 패키징 (Nginx + Docker)
로컬에서의 코딩이 모두 끝나고 **"실제 운영 서버(AWS 등)에 올리기 위해 튼튼하게 제품으로 포장(Build)한 상태"**입니다. 우리가 작성한 무거운 리액트 코드 원본을, 가장 작고 가벼운 정적 파일(HTML/JS) 덩어리로 변환(`build`)한 다음, 실무에서 사용하는 강력한 웹 서버 프로그램인 **Nginx**에 탑재해서 도커 컨테이너로 서비스합니다.

### ❓ 언제 사용하나요?
- 프론트엔드쪽 작업이 끝났고, **"드디어 백엔드 API 서버랑 DB까지 싹 다 한 번에 묶어서 실제처럼 테스트해보자!"** 할 때 사용합니다.
- 🚨 **[주의사항]** : 이 상태는 이미 "완성본으로 포장(build)" 된 상태이기 때문에, 여기서 여러분이 코드 몇 줄을 수정하더라도 4000번 페이지에서는 수정된 내용이 절대로 자동으로 반영되지 않습니다.

### 💻 실행 및 재빌드 방법
도커 명령어이므로 프로젝트 **최상단(root) 폴더**에서 실행해야 합니다.

**처음 백엔드/DB/프론트엔드를 한 방에 띄울 때:**
```bash
docker compose up -d
```

**개발모드(5173 번)에서 디자인 코드를 막 수정하다가 완성했는데, 그 완성된 최신본을 이 4000번 배포용 도커 컨테이너에도 똑같이 덮어씌워주고(재빌드) 싶을 때:**
```bash
# 프론트엔드 이미지만 새로 포장(빌드)하면서 반영
docker compose up -d --build frontend
```
👉 **접속 주소:** `http://localhost:4000`

### 📝 결론: 프론트엔드 개발 워크플로우 (추천)
> 디자인, 코드를 계속 고쳐야 할 때는 로컬 터미널을 따로 열어서 **`npm run dev` (`5173 포트`)** 화면을 보면서 실시간으로 편하게 작업하세요.
> 
> "오케이 완벽해!" 싶어서 작업이 종료되는 시점에, **`docker compose up -d --build frontend`** 를 한 번 입력해서 **`4000 포트(통합 배포환경)`**로 결과물을 덮어씌워두시면 됩니다!
